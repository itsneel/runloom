# Runloom Studio

This folder is a project grouping, not an npm or Angular project. Run application commands inside the relevant project directory. Run `make` and `node scripts/...` commands below from the repository root. Build and formatting configuration, dependency manifests and licenses belong to each independent project.

External API and End workflow nodes are available in the node picker. Team administrators manage write-only API credentials under Workspace settings → Workflow secrets. See [API nodes and secrets](../docs/api-nodes-and-secrets.md) for operator setup and `make test-ui-api-nodes` browser checks.

Team admins manage backend integrations under **Workspace settings → Service accounts**. Select scopes, exact published main versions, disclosure fields and quotas. New client secrets are shown only once on creation/rotation and never saved in browser storage. Provisioning requires the optional Keycloak configuration described in [consumer execution setup](../docs/consumer-api.md). Run `node scripts/service-accounts-smoke.mjs` against the development server for browser regression coverage.

This directory groups three **independent Angular projects**, not one Angular/npm workspace. [Host](projects/host/README.md) owns sign-in, workspace selection, navigation, appearance and dialogs. [Workflows](projects/workflows/README.md) owns authoring, versions, schedules and runs. [Management](projects/management/README.md) owns teams, membership, service accounts, secrets, analytics and budgets. Each project has its own package manifest, lockfile, node_modules, Angular/TypeScript/Webpack configuration, tests, Dockerfile and dist directory. Copy any project directory into a separate repository and build it without its siblings or this parent directory.

The fourth independent project, [platform library](libraries/platform/README.md), supplies the versioned `@runloom/studio-platform` npm package for auth/session state, permission context, dialogs, themes and runtime contracts. Applications consume a compiled release artifact inside their own `vendor/` directory, never library source or another project's build output. No application build invokes the library build. All API calls remain relative `/api` requests to the Go backend.

The **Projects** page (`/workflows/projects`) organizes every team's workflows into project folders. Search, create or rename folders in the main content area, then open a project to browse its workflows. The workflow dashboard also has a **Project** selector. Move a saved workflow using the Project selector above the canvas. Folder changes are persisted by the Go API using the configured PostgreSQL, MongoDB, or file backend. See [projects and their API](../docs/projects.md).

Projects organize authoring and testing only; they are not required to execute a published workflow through the API. **Test workflow** starts a real published-version execution, not a sandbox run. Execution remains protected by team permissions, independently of the selected project or whether the Studio is open.

## Local development

Use **Schedules** in the editor header for recurring or one-time starts, saved input, time zones, pause/resume and Run now. Use **Add node → Subworkflow** to call a separately published same-team workflow, map its input and pin its version. Parent and child runs link to one another. The schedule form participates in unsaved-change protection. See [the walkthrough and execution rules](../docs/schedules-and-subworkflows.md).

Set **Workflow kind → Child — parent calls only** before publishing a reusable child. Only published children appear in the Subworkflow picker; only published main workflows appear in the schedule picker. **Test child workflow** starts an independent test of a published child version, with real activities and side effects. Tests and their nested children are labeled in run history. Normal API, webhook and schedule starts remain blocked. Studio tests use a separate authenticated editor/admin endpoint, which is also callable by clients with those credentials; this is not a browser-only security boundary. See [test execution rules](../docs/schedules-and-subworkflows.md#independent-child-tests).

1. Start the account services with `docker compose --project-directory . -f compose/compose.yaml up -d --wait identity-db mailpit keycloak` from the repository root, then start Temporal, the Go API, and the Go worker.
2. Run `npm ci` separately in each application directory, or run `make setup-ui` from the repository root to install all four projects.
3. Run `make run-ui` from the repository root and open [http://localhost:4200](http://localhost:4200).

The optional repository-level `make run-ui` launcher starts each project's own Angular CLI: host on port 4200, workflows on 4201 and management on 4202. Each also has an independent `npm start` command. Use the host URL. `projects/host/proxy.conf.cjs` forwards remote assets through same-origin `/remotes/workflows/` and `/remotes/management/` paths and proxies `/api` to [http://localhost:8080](http://localhost:8080). Override `RUNLOOM_API_PROXY` and `RUNLOOM_AUTH_PROXY` for another backend/Keycloak address. `RUNLOOM_WORKFLOWS_PORT` and `RUNLOOM_MANAGEMENT_PORT` change remote ports in the launcher; `node scripts/studio-dev-server.mjs --port 4300` from the repository root changes the host port. Development rebuilds are watched; refresh the host after changing a remote.

It also proxies `/auth` to Keycloak on localhost:18081. Register and read verification/reset messages in Mailpit at http://localhost:8025. Accounts, Google configuration, organizations, team roles, and permission boundaries are documented in [authentication](../docs/authentication.md). Tokens are held in memory; the studio's API client stays bound to its selected team even when an earlier asynchronous action finishes after a team switch.

## Production build

Inside any application directory, run `npm ci`, `npm test`, and `npm run build`. That application's output is its own `dist/browser/`. Independent root Make targets are `build-host`, `build-workflows`, and `build-management`. The optional repository-level `make build-ui` target launches those independent builds; there is no parent compiler configuration, dependency installation or build cache shared by the projects. Opening a remote directly shows an Angular availability screen; authenticated features are composed through the host at runtime.

Each project's local `angular.json` uses `@angular-builders/custom-webpack:browser` and its own `webpack.config.cjs`. Angular/RxJS/the installed platform package are runtime singletons with strict versions; no application imports another application. Entry points use asynchronous bootstrap. Each project owns its `index-transform.cjs` and license-extractor compatibility adapter. License extraction remains enabled. Local `npm test` and build checks reject source imports outside the project, undeclared packages, sibling package dependencies and inline component resources.

The host reads its `public/federation.manifest.json` at runtime. Remotes are fetched only after sign-in, on demand, with loading/error/retry states. Same-origin remote locations are required because remote JavaScript executes with host privileges. Module Federation is not a security sandbox; Go still authorizes every API request. Independent builds do not remove runtime compatibility requirements: keep Angular and `@runloom/studio-platform` versions compatible across releases. Never initialize Keycloak separately in a remote or persist access tokens in browser storage. The packaged bridge forwards discard guards and confirmed exits, preserving drafts and one-time-secret warnings.

There are three separate Docker images and Helm deployments: `ui` (host), `workflows-ui` and `management-ui`. Each Docker build context is only that application's directory, including its vendored library release; sibling sources are unavailable. The host proxies `/remotes/workflows/` and `/remotes/management/` to the independently deployed asset servers. Host image builds do not depend on either remote image. Keep stable service addresses and retain old hashed chunks while active sessions may reference them. Deploy compatible remotes before switching manifest locations; coordinate breaking contracts. Missing remote assets return 404, not the host HTML fallback.

Every component uses a separate `.ts`, `.html` and `.scss` file (some share SCSS files). Each application’s `npm run check:boundaries`, included in its build, rejects inline component templates/styles and direct imports between applications. Dynamic Angular style bindings for canvas position are allowed; workflow JSON `template` fields are data, not component templates. Run `node scripts/federation-smoke.mjs` against the development host for lazy loading, shared authentication, discard guards, failure/retry and theme continuity checks.

Angular 22 emits Webpack-builder deprecation warnings. Framework/compiler (`22.1.5`) and CLI/build tooling (`22.1.7`) remain pinned. The separate application installs on 2026-10-02 each reported 9 audit findings (4 moderate, 2 high and 3 critical); remediation remains outstanding. The platform library install reported none. Re-run `npm audit` in each project for current details. Nginx images contain compiled assets, not `node_modules`, but this does not establish that shipped code is unaffected.

From the repository root, `make test-ui` builds the UI and `make docker-build-ui` packages the same production build in Docker.

## Visual theme

Studio offers **Mist (Light)** and **Midnight (Dark)** palettes in the platform library's `libraries/platform/src/styles.scss`: cool neutral surfaces, slate text and a restrained indigo accent. Applications use the stylesheet from their installed package. Amber and red are reserved for warnings and failures, with labels and icons so meaning never depends on color alone. Node types share an accent and remain distinguishable by their icons and names.

Use **Appearance** above your sidebar profile to choose Light, Dark or System (the default). System follows live device appearance changes. The preference is stored in this browser, shared across tabs, and applied before Angular starts to avoid a bright initial screen. When browser storage is unavailable, switching still works for the current page. Appearance changes do not navigate or discard drafts. The collapsed rail retains an appearance icon; mobile navigation includes the same control.

Reuse the `--rl-*` tokens for new components instead of adding independent palettes. Use the system font stack without external font requests, subtle panel shadows, and visible keyboard focus. Respect reduced-motion preferences. The builder, analytics, management screens, notices and dialogs share these tokens; the independent website and Keycloak theme are separate.

Run `npm --prefix studio/libraries/platform test` to check text contrast in both palettes, and `node scripts/theme-smoke.mjs` against the development server to verify system preference, persistence, cross-tab synchronization, restricted storage, keyboard access and mobile switching. Browser suites below cover desktop/mobile layouts and interactions; token checks alone are not a complete accessibility audit.

## Workspace navigation

**Cost analytics** in the sidebar shows role-scoped LLM spend, tokens, metered runs, average priced spend and pricing coverage. Date presets are 1 day, 1 week, 1 month, MTD, YTD, 6 months and 1 year (UTC). Sort server-paginated run/team/model breakdowns and inspect the spend trend. Missing or unpriced usage is not zero cost. See [accounting rules, permissions and API](../docs/llm-costs.md#cost-analytics-dashboard); run `node scripts/cost-analytics-smoke.mjs` against the development server for its browser checks.

**LLM budgets** manages reusable **Soft and Hard Limit Policies** across the selected team's projects. Each project gets a separate monthly UTC allowance; all workflows inherit policies by default, with audited administrator-controlled exclusions. Soft limits log warnings. Hard limits pause workflows and show why; resuming rechecks the current budget and retains completed provider responses. The page includes sortable project spend, policy revisions and recent audit events. See [budget semantics and API](../docs/llm-costs.md#soft-and-hard-limit-policies). `node scripts/budget-policies-smoke.mjs` checks policy editing, permissions, unsaved-change guards, exclusions and pause messaging in the browser.

Studio uses one stable, collapsible left sidebar. **Workflows** and **Projects** appear above the permanently expanded **Management** section on every page. Project folders and workflow lists render in the main content area, never above Management. The navigation area scrolls independently and keeps its scroll position during route changes; appearance and account controls stay at the bottom. Select the organization and team names in the top breadcrumb bar to switch workspaces. The same control is available with the sidebar collapsed and on mobile. On desktop, collapsing leaves a persistent icon rail with labels on hover or keyboard focus; Escape dismisses the label. The Projects icon navigates directly to Projects without expanding the rail. Collapsing does not discard the current workflow. Team management has selectable team cards, member search, role controls, and a separate organization-members page. Service accounts and workflow secrets each have their own page; only the active page is mounted. Viewer and administrator permissions still determine the available actions.

Changing pages, teams, or organizations retains the existing unsaved-workflow and management-draft guards, including one-time credentials. On small screens the sidebar opens as an overlay with keyboard focus containment, Escape/backdrop dismissal, and an inactive content pane. `node scripts/workspace-navigation-smoke.mjs` runs mocked desktop/mobile navigation, member management, stale-response and permission checks; it is included in `make test-ui-browser`.

## Notifications

Builder confirmations use a compact bottom-right toast, clear after six seconds, and pause while hovered or keyboard-focused. Errors stay visible until dismissed or replaced by a later action. Notifications never move keyboard focus; messages render as text, with polite status announcements and assertive error announcements. Reduced-motion preferences are respected. Opening a workflow no longer produces a success popup.

Feedback stays inside the active schedule/JSON dialog or run/version drawer, without covering its controls. Organization, service-account and secret messages use the same Angular `Notice` component inline, without timed dismissal. The persistent editing-access strip distinguishes preview, reserved editing and interrupted access, with an unsaved-JSON recovery action when editing is interrupted. Its underlying locking and unsaved-change rules are unchanged.

Run `node scripts/notifications-smoke.mjs` against the development server for timing, hover/focus, keyboard dismissal, mobile, reduced-motion, escaped-content and schedule-placement checks. It accepts the same Playwright/Chrome environment options as the other browser scripts and is included in `make test-ui-browser`.

## Unsaved workflow changes

The builder displays “Unsaved changes” when the workflow differs from its loaded or saved snapshot. Closing or reloading the tab and leaving the site trigger the browser's native warning. Signing out, switching workflows, projects, versions, teams, organizations, or opening organization management asks before discarding edits. Cancel keeps the current workflow and workspace selection.

Unapplied advanced-editor JSON and invalid node input JSON are protected too. Closing the JSON editor asks before discarding its changes. Applying JSON only updates the builder; Save or Publish persists it. Validation and failed saves do not clear the warning. Edits made while saving remain unsaved and are not overwritten by the response. Loading another workflow also preserves edits made while its request is pending.

Browser exit dialogs use browser-controlled wording and require prior user interaction. They cannot guarantee protection against browser crashes, force-quits, or mobile process termination. This feature does not autosave or recover drafts after a crash.

For browser regression checks, start the development servers with `make run-ui` from the repository root, then run `node scripts/unsaved-changes-smoke.mjs`. The script requires Playwright (resolvable as `playwright`, or via `RUNLOOM_PLAYWRIGHT_MODULE` pointing to its module). Set `RUNLOOM_CHROME` for a system Chrome executable and `RUNLOOM_UI_URL` for a non-default development URL. It uses development-only Angular debug APIs and mocked API responses; no backend, real login, or database is required. It covers canceled and confirmed navigation, native exit dialogs, JSON edits, failed saves, and edits made during asynchronous requests. Do not point it at a production build.

The included Docker image builds the application and serves it with Nginx. Nginx proxies `/api` to the `api` container and `/auth` to Keycloak in the repository Compose stack. Hosted Helm uses its configured external identity URL instead.

The image runs as UID 101 and listens on port 8080 inside the container. Root Compose publishes it on localhost:4200; the Helm chart supplies the release-specific API upstream through a ConfigMap. See [the deployment guide](../docs/deployment.md).

Platform 1.8.0 adds Lumi draft coordination through the workflow port. The port carries only IDs, scope and an exact result hash; the owning workflow app keeps its edit token private and performs authenticated draft saves. Keep host, workflows, management and platform-admin on the same packaged platform version because Module Federation requires an exact match.
